# B 方案设计与可核验证据

本说明服务于课程报告与答辩，描述交付代码中实际存在的设计，不代表真实学生人工工作量记录。

## 一、层次结构

```text
Console：main.cpp 词法解析、参数数目、中文帮助、输出及错误反馈
    ↓
Application：SchoolService，业务权限、业务校验、事务候选、查询、统计、导出
    ↓
Domain：Account、Student、Teacher、SchoolClass、Subject、State
        RolePolicy ← AdminPolicy / TeacherPolicy / StudentPolicy
    ↓
Infrastructure：Repository、encode/decode、atomicWrite、SHA-256
```

`RolePolicy` 是抽象角色策略，具有虚析构函数与 `administer()`、`teach(...)`、`seeStudent(...)` 三个纯虚操作；三种派生策略通过覆盖行为形成运行时多态。`SchoolService` 组合 `Repository` 和 `State`，不使用多重继承。

领域对象用 `std::map` 按学号、账号、工号等索引；教师以 `std::set` 保存多个所辖班级；成绩以“学号、科目”二元键唯一保存。学生资料、教师资料与登录账号分开保存并校验双向关联，避免删除账号后残留孤立资料。

## 二、类和主要接口

| 类型 | 职责 | 关键操作或字段 |
|---|---|---|
| Account | 登录凭据、启用状态、角色及业务对象关联 | login、salt、hash、role、enabled、ref |
| Student | 学籍档案 | id、account、name、gender、year、classId、contact |
| Teacher | 教师档案及多班授权 | id、account、name、classes |
| SchoolClass / Subject | 教务目录 | id、name |
| State | 完整可验证业务状态 | accounts、students、teachers、classes、subjects、grades |
| RolePolicy / 三个派生类 | 集中角色权限策略 | administer、teach、seeStudent |
| Repository | 文件边界、快照与日志、规范导出 | load、save、audit、logs、artifact、backup |
| SchoolService | 唯一业务入口与实时授权 | login、changePassword、students、setGrade、importGrades、rank、stats、addUsers、usersAction、restore |
| Summary / Stat / RankRow | 统计中间结果 | 已录数/总分/均分/GPA、人数与分段、学生名次 |

所有业务接口以 `Session` 的账号标识重新读取现有账号状态。`actor()` 检查存在和启用；`classAccess()` 检查班级范围；`studentAccess()` 检查本人或辖班权限；`admin()` 执行管理员限制。私有数据访问与公有服务接口分开，普通调用方没有公开的原始数据引用。

## 三、典型流程与算法

### 批量成绩导入

1. 验证当前会话及可导入角色。
2. 将 `State` 复制为候选状态，按行读取外部文本。
3. 检查列数、学生存在、科目存在、教师辖班、同批重复键与有限数字范围。
4. 任何异常立即抛出，候选状态丢弃，原数据库不变。
5. 全部通过后 `commit()` 验证整体引用，保存快照，再替换内存状态并记日志。

账号批量创建、禁用和删除采取相同的“先验证完整候选、后提交”结构。恢复备份先 `decode()` 得到候选状态，成功验证才备份旧状态并提交。

### 排名

总分和均分先过滤未完成所有科目的学生，单科过滤未录入学生；按数值降序排列，学号作为同分时稳定展示的次序。顺次赋予竞争名次，排序后与本组首值差不超过 1e-9 时沿用该组名次，否则以当前位置加一开启新组，避免小数加法浮点误差及相邻值链式合并。要求升序时，仅重排展示顺序，保留先前计算的学业名次。查询时重新计算，因此不需要维护可能过期的排名缓存。

### 文件验证

数据库以 `SGM_B_1` 版本标记开头，以 `END` 加 SHA-256 校验结束；各记录使用有标签的文本行。解析严格拒绝多余/缺失字段、重复键、未知记录、非法成绩、孤儿引用和缺失启用管理员。文件内容的校验和用于发现损坏，不构成身份认证或防篡改签名。

### 图表

五个分数段计数同时驱动 SVG 饼图、柱图和文本说明。饼图以累计角度生成扇形，单段占全部样本时绘制完整圆，无成绩则绘制灰色空状态。柱高依人数归一，柱顶标明真实整数人数；图表与统计快照输出到同一数据根的分类目录。

## 四、真实迭代记录

以下是实现过程中确实发现并修正的问题，可作为报告中的实际调试依据：

1. **升序显示改变名次含义**：初稿在排序后直接按当前位置赋名次，升序时低分被标成第 1。修复为先按降序算学业名次，再按需要改变显示顺序；自测验证 CPP 升序先显示王五，仍为第 3。
2. **Windows 路径反斜杠被当作转义**：通用 `std::quoted` 适合程序序列化，却不适合直接读取用户写的 `C:\...` 命令路径。交互词法改为双引号只分组、反斜杠保持原样；独立 CLI 验证覆盖中文、空格和反斜杠路径。
3. **add-student 参数数误计**：命令实际有八个业务参数、加命令总数九项；修正参数数量校验，使文档示例可直接执行。
4. **日志写入失败与提交结果不一致**：原先数据保存成功后日志失败会抛出笼统错误。修复为明确显示“数据已保存，但操作日志写入失败”，且 CLI 再次写失败日志也有独立异常保护。自测用同名目录代替 `audit.log` 重现不可写情况，核对已提交数据与提示内容。
5. **小数成绩分段标签歧义**：实际分段以 `<60` 等条件计算，最初的“0–59”标签无法表达 59.5。标签调整为 `[0,60)` 等区间，并保留 `[90,100]` 的闭合上界。

6. **Windows 启动参数中文编码风险**：交互文本已是 UTF-8，但系统传给窄字符 `main` 的路径可能受系统代码页影响。修复为 Windows 入口通过 `CommandLineToArgvW` 获取 Unicode 参数，使用 `WideCharToMultiByte` 显式转 UTF-8；参数存于 `vector<string>` 内保证生命周期。Python 子进程指定“中文 数据目录”进行创建、查询及重启，3/3 检查通过。

7. **小数总分的同分误判**：真实测试发现 0.1+0.2+0.3 与 0.3+0.2+0.1 虽然数学总和一致，但 double 累加末位误差导致并列被拆成 1、2。保留原始数值排序，按组首差不超过 1e-9 赋并列名次；新增总分与均分两项回归，全部自测达到 74/74。

完成修改后使用 clang-format 按四空格缩进、100 列格式化全部源码，并再次编译和执行自测。
